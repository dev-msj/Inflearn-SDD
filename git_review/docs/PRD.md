# PRD: git_review

## 1. 개요

### 프로젝트 목적
GitHub 저장소가 사용자가 작성한 SDD(사양 주도 개발) 스펙 문서에 명시된 산출물을 실제로 갖추고 있는지 항목별로 확인하고, 준수율을 한 화면에서 확인하게 한다.

### 타겟 사용자
- **SDD 방식으로 개인 프로젝트를 진행하는 개발자**: PRD/TECH_SPEC을 먼저 쓰고 구현하지만, 문서에 적어둔 산출물을 실제로 다 만들었는지 수동으로 대조하고 있다.
- **스터디·강의 수강자 및 멘토**: 여러 저장소가 정해진 문서·폴더 구조를 따르는지 반복 확인해야 한다.

공통 특성: GitHub 계정을 보유하고 있으며, 스펙 문서를 마크다운 파일로 관리한다. 검증 이력을 남기는 것보다 지금 이 순간의 준수 여부를 즉시 확인하는 것을 우선한다.

### 핵심 가치 제안
스펙 문서와 저장소를 눈으로 번갈아 대조하던 작업을, 문서 업로드와 저장소 선택만으로 항목별 체크리스트와 준수율(%)로 바꿔준다. 별도 설치나 계정 생성 없이 GitHub 로그인 한 번으로 사용할 수 있고, 업로드한 문서와 결과는 어디에도 저장되지 않는다.

## 2. 기능 요구사항

### 기능 1: GitHub 로그인 및 검증 대상 저장소 선택

**사용자 스토리**
> SDD 방식으로 개발하는 개발자로서, GitHub 계정으로 로그인해 내 저장소 중 하나를 검증 대상으로 선택하고 싶다, 별도 계정 가입이나 저장소 주소 입력 없이 바로 검증을 시작하기 위해

**수용 기준**
- [ ] 로그인하지 않은 상태로 접속하면 "GitHub으로 로그인" 진입점만 노출되고, 인증을 마치면 로그인한 계정명과 프로필 이미지가 화면 상단에 표시된다.
- [ ] 로그인 성공 시 사용자가 접근 권한을 가진 저장소 목록이 최근 수정일 내림차순으로 표시되며, 각 항목에 저장소명·기본 브랜치명·공개/비공개 여부가 함께 표시된다.
- [ ] 검색창에 문자열을 입력하면 저장소명에 해당 문자열을 포함하는 항목만 남고, 목록에서 저장소 1개를 선택하면 "검증 대상"으로 화면에 고정 표시된다.
- [ ] (엣지) 접근 가능한 저장소가 0개이면 빈 화면 대신 "검증할 저장소가 없습니다"라는 안내와 다음 행동 안내 문구를 표시한다.
- [ ] (엣지) 저장소가 100개를 초과하면 목록을 나누어 순차 로드하며, 추가 로드 후에도 이미 선택한 저장소의 선택 상태가 유지된다.
- [ ] (에러) 사용자가 GitHub 인증을 취소하거나 권한을 거부하면 로그인 화면으로 돌아가 "인증이 취소되었습니다. 다시 시도해 주세요" 메시지를 표시하고, 화면 오류 없이 재시도할 수 있다.
- [ ] (에러) 로그아웃하거나 세션이 만료되면 계정 정보·저장소 목록·업로드한 문서·검증 결과가 화면에서 모두 제거되고 로그인 화면으로 돌아간다.

### 기능 2: SDD 스펙 문서 업로드 및 기대 산출물 목록 추출

**사용자 스토리**
> 스펙 문서를 관리하는 개발자로서, 내 PRD/TECH_SPEC 문서를 업로드해 문서가 요구하는 산출물 목록을 자동으로 뽑아내고 싶다, 검증 항목을 하나씩 손으로 입력하지 않기 위해

**수용 기준**
- [ ] 마크다운 문서를 파일 선택 또는 끌어놓기로 최대 2개까지 업로드할 수 있고, 업로드 직후 각 파일의 이름과 크기가 화면에 표시된다.
- [ ] 업로드된 문서에서 기대 산출물(파일 경로 및 폴더 경로) 목록을 추출해 화면에 나열하며, 각 항목마다 어느 문서의 어느 위치에서 추출되었는지 출처를 함께 표시한다.
- [ ] 추출된 항목을 사용자가 개별 삭제하거나 새 경로를 직접 추가할 수 있고, 수정 결과가 즉시 목록과 총 항목 수에 반영된다.
- [ ] (엣지) 두 문서에서 동일한 경로가 추출되면 하나의 항목으로 병합되며, 출처는 두 건 모두 표시된다.
- [ ] (엣지) 문서에서 산출물을 하나도 추출하지 못하면 "기대 산출물을 찾지 못했습니다" 안내와 함께 수동 입력 수단을 제공해, 사용자가 검증을 계속 진행할 수 있다.
- [ ] (에러) 마크다운(.md) 이외의 확장자이거나 파일 크기가 1MB를 초과하면 업로드를 거부하고, 허용 확장자와 최대 크기를 명시한 오류 메시지를 표시한다.

### 기능 3: 산출물 존재 여부 체크리스트 및 준수율 대시보드

**사용자 스토리**
> 저장소 상태를 점검하는 개발자로서, 기대 산출물이 실제 저장소에 존재하는지 항목별 체크리스트와 준수율로 확인하고 싶다, 문서와 저장소를 눈으로 대조하지 않고 빠진 산출물을 곧바로 찾아내기 위해

**수용 기준**
- [ ] 검증을 실행하면 기대 산출물 각 항목에 대해 "존재" 또는 "없음" 상태가 표시되고, 준수율(존재 항목 수 ÷ 전체 항목 수 × 100)이 소수점 첫째 자리까지 표시된다.
- [ ] 준수율이 80% 이상이면 PASS, 80% 미만이면 FAIL 판정이 결과 화면 상단에 표시되며, 판정 기준값이 화면에 함께 안내된다.
- [ ] "없음" 항목만 모아 보는 필터를 제공하고, "존재" 항목은 해당 저장소의 파일 위치로 이동할 수 있는 링크를 제공한다.
- [ ] 검증 진행 중에는 전체 항목 수 대비 확인 완료 항목 수가 표시되며, 항목 50개 기준으로 결과 표시까지 15초 이내에 완료된다.
- [ ] (엣지) 기대 산출물이 폴더 경로인 경우, 해당 폴더 하위에 파일이 1개 이상 존재하면 "존재"로 판정한다.
- [ ] (엣지) 대상 저장소에 파일이 하나도 없으면 준수율 0%, 판정 FAIL과 함께 "저장소에 파일이 없습니다" 안내를 표시한다.
- [ ] (에러) 저장소 조회 권한 부족, 요청 한도 초과, 네트워크 오류가 발생하면 원인별 안내 메시지와 재시도 수단을 제공하며, 직전 결과를 부정확한 값으로 덮어쓰지 않는다.

## 3. 비기능 요구사항

### 성능
- 로그인 완료 후 저장소 목록 첫 화면 표시까지 3초 이내.
- 기대 산출물 50개 기준, 검증 실행부터 결과 표시까지 15초 이내.
- 문서 업로드 후 기대 산출물 목록 표시까지 5초 이내.

### 보안
- GitHub 인증 정보는 사용자 세션 동안에만 유지되며, 로그아웃 또는 세션 종료 시 즉시 폐기된다.
- 업로드한 스펙 문서 내용과 검증 결과는 영구 저장되지 않으며, 세션 종료 후 다시 조회할 수 없다.
- 저장소 접근 범위는 로그인한 사용자가 이미 접근 권한을 가진 저장소로 한정되며, 읽기 목적 이외의 저장소 변경은 일어나지 않는다.
- 화면 어디에도 인증 정보 원문이 노출되지 않는다.

### 접근성
- 로그인, 파일 업로드, 저장소 선택, 검증 실행의 모든 단계를 키보드만으로 수행할 수 있다.
- 판정 결과(PASS/FAIL)와 항목 상태(존재/없음)는 색상뿐 아니라 텍스트와 아이콘으로도 구분된다.
- 본문 텍스트와 배경의 명도 대비는 4.5:1 이상을 유지한다.
- 너비 1280px 데스크톱과 768px 태블릿 화면에서 가로 스크롤 없이 모든 기능을 사용할 수 있다.

## 4. 제약사항

### 기술적 제약
- 저장소 내용은 GitHub이 제공하는 조회 수단을 통해 읽기 전용으로만 접근하며, 저장소 전체를 로컬로 내려받지 않는다.
- 데이터베이스를 사용하지 않으므로 세션을 벗어나는 상태(검증 이력, 즐겨찾기, 사용자 설정)를 보존할 수 없다.
- GitHub의 시간당 요청 한도 내에서 동작해야 하며, 한도 초과 시 검증을 중단하고 사용자에게 안내한다.
- 검증 대상은 GitHub에 호스팅된 저장소로 한정한다.

### 비즈니스 제약
- MVP 범위는 위 3개 기능으로 고정하며, 범위 확장은 MVP 검증 이후에 판단한다.
- 사용자 데이터를 저장하지 않는 것을 전제로 설계하므로, 저장이 필요한 기능은 MVP에 포함하지 않는다.
- 유료 결제 및 조직 단위 라이선스 요건은 고려하지 않는다.

## 5. 성공 지표
- 로그인 완료부터 첫 검증 결과 확인까지 걸리는 시간이 신규 사용자 기준 3분 이내 (테스트 참가자 10명 중 8명 이상 달성).
- 로그인 → 문서 업로드 → 저장소 선택 → 결과 확인까지의 완주율 70% 이상 (세션 기준).
- 검증 결과의 항목별 판정 정확도 95% 이상 (샘플 저장소 20개, 수동 대조 결과와 비교).
- 검증 실행 요청 중 오류로 결과를 받지 못한 비율 5% 미만.
- 결과 화면에서 "없음" 항목 필터를 사용하는 세션 비율 50% 이상 (핵심 가치 사용 여부 확인).

## 비범위 (Out of Scope)
아래 항목은 MVP에서 다루지 않는다.
- 데이터베이스 도입 및 검증 이력 저장·조회 (업로드 문서, 검증 결과 모두 미저장).
- 저장소 전체를 내려받아 수행하는 코드 정적 분석.
- 함수·모듈 단위로 스펙과 구현 로직의 정합성을 대조하는 검증 (MVP는 산출물 존재 여부만 판정).
- 다중 사용자·팀 협업 기능 (결과 공유, 권한 관리, 조직 단위 대시보드).
- GitHub 외 저장소 호스팅 서비스 지원.
- 검증 결과에 따른 자동 수정, 이슈 생성, PR 생성.

---

## 향후 확장 (MVP 이후)
- 검증 이력 저장 및 준수율 추이 비교.
- 여러 저장소 일괄 검증과 결과 비교 화면.
- 검증 결과를 마크다운 체크리스트나 파일로 내보내기.
- 산출물 존재 여부를 넘어 문서 내 요구사항과 구현 내용의 정합성 검증.
- 팀 단위 공유 링크 및 조직 저장소 일괄 점검.
- 판정 기준(PASS 기준 준수율) 사용자 지정.
