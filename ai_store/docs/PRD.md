# PRD: ai_store (AI 프롬프트 템플릿 스토어)

> 작성일: 2026-08-10
> 상태: MVP 정의 완료 (기능 3개)

## 1. 개요

### 프로젝트 목적
운영자가 직접 제작한 AI 프롬프트 템플릿을 국내(KRW)와 해외(USD) 구매자 모두에게 온라인으로 판매하고, 구매자가 즉시 프롬프트 전문을 열람할 수 있게 한다.

### 타겟 사용자

| 사용자 유형 | 특성 | MVP에서의 역할 |
|---|---|---|
| 구매자 (국내) | 한국어 사용, 원화 결제 선호, ChatGPT/Claude 등 AI 도구를 업무나 학습에 사용 | 템플릿 탐색 → KRW 결제 → 열람 |
| 구매자 (해외) | 영어권 포함 해외 거주, 달러 결제 필요 | 템플릿 탐색 → USD 결제 → 열람 |
| 운영자 (단독 판매자) | 스토어의 유일한 판매자. 모든 템플릿을 직접 제작·등록 | 상품 등록·관리 (관리자 화면, 별도 온보딩 절차 없음) |

> MVP는 **운영자 단독 판매 구조**다. 외부 판매자 가입, 심사, 정산은 다루지 않는다.

### 핵심 가치 제안
- **검증된 프롬프트를 즉시 사용**: 구매 직후 프롬프트 전문을 복사·다운로드해 바로 AI 도구에 붙여넣을 수 있다.
- **구매 전 품질 확인**: 상세 페이지에서 일부가 마스킹된 미리보기를 제공해, 구매 전에 프롬프트의 구조와 톤을 확인할 수 있다.
- **거주 지역 무관한 결제**: 구매자가 원하는 통화(KRW/USD)를 직접 선택해 각 통화에 맞는 결제 수단으로 결제한다.

## 2. 기능 요구사항

### 기능 1: 템플릿 탐색 및 상세 미리보기

**사용자 스토리**
> 구매자로서, 카테고리와 검색으로 프롬프트 템플릿을 찾고 상세 페이지에서 미리보기를 확인하고 싶다, 구매 전에 내 목적에 맞는 템플릿인지 판단하기 위해

**수용 기준**
- [ ] (정상) 목록 화면 접속 시 판매 중인 템플릿이 제목, 카테고리, 가격(KRW/USD 병기), 대표 이미지와 함께 표시되고, 한 페이지에 20개 단위로 노출된다.
- [ ] (정상) 카테고리를 선택하면 해당 카테고리에 속한 템플릿만 남고, 선택한 카테고리가 화면에 표시된다. 카테고리 선택은 검색어와 동시에 적용된다.
- [ ] (정상) 검색창에 키워드를 입력하면 템플릿 제목과 설명에 해당 키워드를 포함한 템플릿이 결과로 표시된다.
- [ ] (정상) 상세 페이지에는 제목, 설명, 카테고리, 가격, 사용 예시 안내, 미리보기 영역이 모두 표시된다.
- [ ] (정상) 미리보기 영역은 프롬프트 전문 중 **앞부분 최대 30%만** 노출하고 나머지는 마스킹 처리되며, "구매 후 전문 열람 가능" 문구가 함께 표시된다.
- [ ] (엣지) 미구매 상태에서는 어떤 경로로도 마스킹된 영역의 원문이 노출되지 않는다. 화면 소스, 페이지 저장, 복사 등 어떤 방법으로도 마스킹 구간의 원문 텍스트를 얻을 수 없다.
- [ ] (엣지) 검색 결과가 0건이면 "검색 결과가 없습니다" 안내와 함께 전체 목록으로 돌아가는 경로를 제공한다.
- [ ] (엣지) 판매 중지되었거나 삭제된 템플릿의 상세 페이지에 접근하면 "현재 판매하지 않는 템플릿입니다" 안내를 표시하고 구매 버튼을 노출하지 않는다. 단, 이미 구매한 사용자는 내 라이브러리에서 계속 열람할 수 있다.
- [ ] (에러) 목록 또는 상세 정보를 불러오지 못하면 빈 화면 대신 오류 안내와 재시도 수단을 표시한다.

### 기능 2: 통화 선택 기반 결제 및 주문 생성

**사용자 스토리**
> 구매자로서, 결제 통화를 KRW 또는 USD 중 직접 선택해 결제하고 싶다, 내 결제 수단으로 문제없이 템플릿을 구매하기 위해

**수용 기준**
- [ ] (정상) 로그인한 사용자가 구매를 시작하면 결제 화면에서 **KRW 또는 USD를 명시적으로 선택**하며, 선택한 통화의 최종 결제 금액이 결제 진행 전에 표시된다.
- [ ] (정상) KRW를 선택하면 국내 결제(토스페이먼츠) 흐름으로, USD를 선택하면 해외 결제(Paddle) 흐름으로 이동한다. IP나 접속 국가로 통화를 자동 결정하지 않는다.
- [ ] (정상) 결제 수단 제공자가 결제 성공을 확정 통지(웹훅)하면 주문이 "결제 완료" 상태로 확정되고, 해당 템플릿이 구매자의 라이브러리에 추가된다.
- [ ] (정상) 주문 확정 시 구매자의 가입 이메일로 주문 번호, 템플릿명, 결제 통화·금액, 라이브러리 접근 경로가 포함된 구매 확인 메일이 발송된다.
- [ ] (엣지) 주문은 **웹훅 통지를 기준으로만 확정**한다. 결제 후 브라우저가 돌아오는 리디렉션만으로는 주문을 확정하지 않으며, 웹훅 도착 전이면 "결제 확인 중" 상태를 보여주고 확정 시 자동으로 화면이 갱신된다.
- [ ] (엣지) 동일 웹훅이 중복 수신되어도 주문과 라이브러리 항목은 1건만 생성된다(중복 지급 없음).
- [ ] (엣지) 이미 구매한 템플릿을 다시 구매하려 하면 결제 진행 전에 "이미 보유한 템플릿입니다" 안내와 라이브러리 이동 경로를 제공하고 중복 결제를 차단한다.
- [ ] (엣지) 결제 진행 중 템플릿 가격이 변경되어도, 결제 화면에 표시된 금액으로 결제가 완료된다.
- [ ] (엣지) 결제 화면 진입 후 30분 내에 결제가 완료되지 않으면 해당 결제 시도를 만료 처리하고, 재시도 시 새 금액으로 다시 시작한다.
- [ ] (에러) 결제 실패(카드 거절, 한도 초과, 사용자 취소 등) 시 주문은 "결제 완료"로 전환되지 않고 실패 사유 안내와 재시도 경로를 제공한다. 실패한 시도는 라이브러리에 어떤 항목도 추가하지 않는다.
- [ ] (에러) 결제는 성공했으나 주문 확정이 지연·실패한 경우, 해당 결제 건은 미확정 상태로 기록되어 운영자가 조회할 수 있고 구매자에게는 "확인 중, 최대 24시간 내 처리" 안내가 표시된다. 결제 금액을 받은 상태에서 라이브러리 미지급으로 끝나는 경우가 없어야 한다.
- [ ] (에러) 환불 요청은 구매일로부터 7일 이내이면서 해당 템플릿의 전문을 아직 열람·다운로드하지 않은 경우에만 접수되며(디지털 콘텐츠 특성 반영), 환불이 확정되면 해당 템플릿은 라이브러리에서 즉시 접근 불가로 전환된다. 정책 문구는 결제 화면에서 결제 전에 표시하고 동의를 받는다.

### 기능 3: 내 라이브러리에서 구매 프롬프트 열람·다운로드

**사용자 스토리**
> 구매자로서, 구매한 프롬프트의 전문을 언제든 다시 열람하고 복사·다운로드하고 싶다, 필요할 때마다 AI 도구에 바로 사용하기 위해

**수용 기준**
- [ ] (정상) 로그인 후 내 라이브러리에 접근하면 구매 확정된 템플릿이 구매일 최신순으로 표시되며, 각 항목에서 전문 열람 화면으로 이동할 수 있다.
- [ ] (정상) 전문 열람 화면에서는 마스킹 없이 프롬프트 전체가 표시되고, "전체 복사" 동작으로 전문이 클립보드에 복사되며 복사 완료가 화면에 표시된다.
- [ ] (정상) 다운로드를 선택하면 프롬프트 전문이 담긴 텍스트 파일이 저장되고, 파일 내용은 화면에 표시된 전문과 동일하다.
- [ ] (정상) 구매 이력은 계정에 귀속되어, 다른 기기에서 동일 계정으로 로그인해도 같은 라이브러리 목록이 표시된다.
- [ ] (엣지) 구매하지 않은 템플릿의 전문 열람 경로에 직접 접근하면 접근이 거부되고 상세 페이지로 안내된다.
- [ ] (엣지) 구매 이후 운영자가 템플릿 내용을 수정하면 구매자는 최신 버전을 열람하며, 마지막 수정일이 함께 표시된다.
- [ ] (엣지) 구매 내역이 없으면 빈 목록 대신 "아직 구매한 템플릿이 없습니다" 안내와 템플릿 목록으로 가는 경로를 표시한다.
- [ ] (에러) 로그인하지 않은 상태로 라이브러리에 접근하면 로그인 화면으로 이동하고, 로그인 성공 후 원래 요청한 화면으로 되돌아간다.
- [ ] (에러) 환불 완료된 템플릿의 열람을 시도하면 "환불 처리된 템플릿입니다" 안내를 표시하고 전문을 노출하지 않는다.

## 3. 비기능 요구사항

### 성능
- 템플릿 목록·상세 화면은 정상 네트워크 환경에서 사용자가 콘텐츠를 볼 수 있을 때까지 2.5초 이내.
- 검색 결과는 입력 완료 후 1초 이내 표시.
- 결제 완료 통지 수신 후 60초 이내에 라이브러리에 템플릿이 반영.
- 동시 접속 100명, 동시 결제 10건까지 위 기준을 유지.

### 보안
- 이메일 회원가입 기반 자체 계정. 비밀번호는 복구 불가능한 형태로 저장.
- 미구매 상태에서 프롬프트 전문(마스킹 구간)이 어떤 경로로도 전달되지 않아야 한다.
- 결제 카드 정보는 스토어가 직접 보관하지 않으며, 결제 제공자 화면에서 처리.
- 결제 제공자의 확정 통지는 발신자 검증을 통과한 요청만 주문 확정에 사용.
- 라이브러리·주문 조회는 본인 계정의 데이터만 접근 가능.

### 접근성 / 사용성
- 모바일(360px 이상)과 데스크톱에서 가로 스크롤 없이 사용 가능.
- 주요 화면(목록, 상세, 결제, 라이브러리)은 키보드만으로 조작 가능하며 본문 텍스트 명도 대비 4.5:1 이상.
- 화면 문구는 한국어/영어 2개 언어로 제공(해외 구매자 결제 흐름 포함).

## 4. 제약사항

### 기술적 제약
- 결제 수단은 토스페이먼츠(KRW)와 Paddle(USD) 두 가지로 한정하며, 각 제공자가 허용하는 결제 흐름과 통지 방식을 벗어날 수 없다.
- 주문 확정은 결제 제공자의 확정 통지에 의존하므로, 통지 지연 시 확정도 지연될 수 있다.
- 상품은 디지털 텍스트 콘텐츠로 한정(파일 번들, 이미지 자산 등은 MVP 제외).

### 비즈니스 제약
- 운영자 단독 판매. 외부 판매자 입점·정산 기능 없음.
- 해외 판매 시 Paddle이 판매자(Merchant of Record)로서 부가세·세금 처리를 담당하는 구조를 전제로 하며, 국내 결제분에 대한 세금계산서·현금영수증 처리는 운영자 책임.
- 국내 전자상거래법상 디지털 콘텐츠 청약철회 제한 규정을 준수해야 하며, 열람 전 7일 환불 정책은 이 규정에 근거해 결제 전 고지·동의가 필수.
- MVP 기능은 3개로 고정하며 범위 추가는 MVP 출시 이후 검토.

## 6. 범위 밖 (Out of Scope)

MVP에서 **명시적으로 제외**하는 항목:

- **판매자 마켓플레이스**: 외부 판매자 가입, 상품 등록 심사, 판매자 대시보드
- **정산**: 판매자별 수익 배분, 정산 주기·명세서, 출금
- **리뷰·평점**: 별점, 후기 작성, 후기 기반 정렬·추천
- **구독 모델**: 월정액 무제한 이용권, 멤버십 등급, 크레딧 제도
- **비회원 구매**: 게스트 결제 및 이메일 링크만으로 열람
- **IP 기반 자동 통화 판별**: 접속 국가·IP로 통화나 결제 수단을 자동 결정 (통화는 사용자가 직접 선택)
- 소셜 로그인, 쿠폰·할인 코드, 장바구니 다건 결제, 추천 알고리즘, 위시리스트, 제휴 마케팅

## 7. 미결 사항 (Open Questions)

결제·주문 영역은 실패 경로가 많아, 아래 항목은 개발 착수 전 확정이 필요하다.

**환불 정책**
1. "열람 전 7일" 기준에서 **열람의 정의**를 어디까지로 볼 것인가? (전문 화면 진입 시점 / 복사 또는 다운로드 실행 시점) → 현재 초안은 열람·다운로드 모두를 열람으로 간주.
2. Paddle(USD) 결제분은 Paddle의 자체 환불 정책 및 구매자 직접 환불 요청 창구가 존재한다. 스토어 환불 정책과 충돌할 때 어느 쪽을 우선할 것인가?
3. 환불 승인 주체는 자동 처리인가 운영자 수동 승인인가? 수동이면 응답 SLA(예: 영업일 2일)를 명시할 것인가?
4. 부분 환불이 필요한 상황(예: 템플릿 내용 하자)이 있는가, 전액 환불만 허용할 것인가?

**결제 실패·확정 처리**
5. 결제 성공 후 확정 통지가 끝내 도착하지 않는 경우, 운영자가 수동으로 주문을 확정할 수 있는 관리 수단이 MVP에 필요한가? (필요 시 4번째 기능이 아닌 기능 2의 운영 보조 화면으로 포함할지 판단 필요)
6. 확정 통지 재시도 정책과 최종 실패 시 알림 대상(운영자 이메일 등)은?
7. 결제 시도 만료 시간 30분은 두 결제 제공자 모두에서 동일하게 적용 가능한가?
8. 결제는 완료되었으나 확정이 지연될 때 구매자에게 안내할 최대 대기 시간(현재 초안 24시간)은 적절한가?

**통화·가격**
9. KRW와 USD 가격을 각각 고정 입력할 것인가, 하나의 기준 통화에서 환산할 것인가? 환산이라면 환율 갱신 주기와 반올림 규칙은?
10. 같은 사용자가 KRW로 결제 실패 후 USD로 재시도하는 경우를 허용하는가?

**계정·데이터**
11. 이메일 인증(가입 시 메일 확인)을 필수로 할 것인가? 미인증 상태에서 결제를 허용할 것인가?
12. 회원 탈퇴 시 구매 이력과 라이브러리 접근권은 어떻게 처리하는가? (즉시 삭제 / 법정 보존 기간 유지)
13. 다운로드 파일 형식은 텍스트 파일 단일로 고정하는가, 다른 형식 요구가 있는가?

**법·세무**
14. 국내 결제분의 현금영수증·세금계산서 발급을 MVP에서 제공하는가, 운영자 수동 대응으로 남기는가?
15. 이용약관·환불 규정·개인정보처리방침 문서의 작성 주체와 검토 일정은?

## 8. 향후 확장 (MVP 이후)

우선순위 순서:

1. **리뷰·평점**: 구매자 후기, 별점, 후기 기반 정렬 (구매 판단 근거 강화)
2. **쿠폰·할인 코드 및 번들 판매**: 다건 결제, 장바구니
3. **구독 모델**: 월정액으로 전체 템플릿 이용
4. **판매자 마켓플레이스 및 정산**: 외부 판매자 입점, 수익 배분
5. **소셜 로그인**, 위시리스트, 개인화 추천
6. **프롬프트 버전 히스토리**: 업데이트 이력 열람 및 이전 버전 비교
