# /sdd-design - TECH_SPEC 작성

## 동작
@architect 에이전트를 호출하여 TECH_SPEC(기술 명세서)를 작성합니다.
TECH_SPEC은 설계뿐 아니라 마지막 장의 **「구현 슬라이스 계획」**까지 포함합니다 —
`/sdd-build`가 계획을 다시 세우지 않고 이 장을 그대로 추출해 작업 문서를 만들기 때문입니다.

## 사용법
```
/sdd-design
```

## 전제조건
- **docs/PRD.md 필수**: PRD가 작성되어 있어야 함
- PRD 부재 시 → "/sdd-plan을 먼저 실행해주세요." 안내 후 중단

## 실행 순서

### Step 1: 전제조건 체크
```
docs/PRD.md 존재 확인
├── 존재 → Step 2로 진행
└── 미존재 → 안내 메시지 출력 후 중단
```

### Step 2: 에이전트 활성화
- @architect 에이전트 호출
- tech-spec-writer 스킬 자동 활성화

### Step 3: PRD 분석
- PRD.md 읽기
- 기능 개수 파악
- 수용 기준 파악
- "PRD.md 분석 중... 기능 N개 확인" 출력

### Step 4: TECH_SPEC 작성
PRD를 기반으로 `docs/TECH_SPEC.md` 작성:
- 기술 스택 선정 (근거 포함)
- 파일 구조 설계
- PRD 기능별 1:1 구현 명세
- 타입 정의, 함수 시그니처
- 검증 매트릭스
- **마지막 장: 「구현 슬라이스 계획」** (`F0 공통 기반` + 기능별 슬라이스, 파일마다 목적/의존/대응 AC)

### Step 5: 슬라이스 계획 검증 (기계적 대조)

계획을 다시 세우지 않고, **세는 것만으로** 판정합니다.

| 검사 | 통과 기준 |
|---|---|
| 장 존재 | 마지막 장 제목이 정확히 `구현 슬라이스 계획` |
| 누락 | 「프로젝트 구조」 장의 모든 파일이 슬라이스 표에 등장 |
| 중복 | 같은 파일 경로가 2회 이상 등장하지 않음 |
| AC 커버리지 | PRD의 모든 수용 기준이 최소 1개 항목의 `대응 AC`에 등장 |
| 실행 작업 | F0에 `⚙️ npm install`(또는 등가 설치 명령)이 있음 |
| 게이트 | 슬라이스마다 완료 게이트 명령이 지정됨 |
| 크기 | 25항목 초과 슬라이스가 없음 |

> 「프로젝트 구조」 트리 자체가 스택 필수 파일(`components.json`, `globals.css`, `lib/utils.ts` 등)을 빠뜨린 경우도 **누락**으로 판정한다 — 트리를 먼저 보완해야 한다.

판정 후 조치:
- **불일치 3건 이하** → 호출자가 해당 장을 직접 보완하고 보완 내역을 사용자에게 보고
- **불일치 4건 이상** → @architect에 부족한 항목만 명시하여 재요청 (최대 1회)
- 재요청 후에도 미충족 → 사용자에게 미해결 항목을 보고하고 진행 여부 확인

### Step 6: 결과 확인
작성된 TECH_SPEC 요약 출력

## 출력물
- `docs/TECH_SPEC.md` (마지막 장에 「구현 슬라이스 계획」 포함)

## 완료 메시지

```
✅ TECH_SPEC 작성 완료

📄 docs/TECH_SPEC.md
- 기술 스택: [스택 요약]
- 파일 구조: N개 파일 설계
- PRD 매핑: 기능 N개 ↔ 구현 명세 N개
- 구현 슬라이스: F0(N) / F1(N) / F2(N) ... 총 N항목
- 검증: 누락 0 · 중복 0 · AC 커버리지 N/N

다음 단계: /sdd-build 로 코드를 구현하세요.
```
