# Tech Spec Writer Skill

## 역할
PRD를 기반으로 구체적인 기술 구현 명세서(TECH_SPEC)를 작성하는 도구입니다.

## 전제조건
- **docs/PRD.md 필수**: PRD가 없으면 작성 불가
- PRD가 없을 경우 → "PRD를 먼저 작성해주세요. `/sdd-plan`을 실행하세요." 안내

## 핵심 규칙

### 1. PRD 필수 참조
- PRD.md를 반드시 먼저 읽고 분석
- PRD의 모든 기능 요구사항을 빠짐없이 반영

### 2. PRD 기능과 1:1 매핑
- PRD에 기능 3개 → TECH_SPEC에 구현 명세 3개
- 매핑 관계를 명시적으로 표시
- 누락된 기능이 없는지 교차 검증

### 3. 구체적 구현 명세
- 파일 경로 명시 (예: `src/components/TodoInput.tsx`)
- 함수명 명시 (예: `addTodo()`, `toggleTodo()`)
- 타입/인터페이스 정의 포함
- Props, State, 훅 인터페이스 정의

### 4. 기술 스택 명시
- 사용할 프레임워크, 라이브러리 버전 포함
- 선정 근거 간략 기술

### 5. 「구현 슬라이스 계획」 장 필수
TECH_SPEC은 **설계이자 구현 계획**이다. `/sdd-build`는 별도 계획 수립 없이 이 장을 기계적으로 추출해 작업 문서를 만든다.
- **항상 마지막 장**에 `## [N]. 구현 슬라이스 계획` 제목으로 배치한다 (장 번호는 프로젝트마다 다름 — 하위 스킬은 **제목으로 찾는다**)
- 「프로젝트 구조」 장의 **모든 파일이 정확히 한 번씩** 등장해야 한다
- 파일마다 `목적 / 의존 / 대응 AC`를 채운다 → 구현 단계에서 재추론이 필요 없게
- 여기 없는 파일은 구현되지 않는다

### 6. 「프로젝트 구조」 장의 완전성
파일 트리는 문서용 요약이 아니라 **구현 대상의 전수 목록**이다. 다음을 빠뜨리지 않는다.
- 루트 설정 파일 (`package.json`, `tsconfig.json`, 빌드/린트/테스트 설정, `.env.example`, 컨테이너 정의)
- **스택 채택상 필수 파일** — 기술 스택을 고른 순간 따라오는 것들
  (예: shadcn/ui 채택 → `components.json`, `src/lib/utils.ts`; Tailwind 채택 → `globals.css`)
- 테스트 파일, 마이그레이션, 시드 데이터

> 이걸 빠뜨리면 구현 단계에서 "트리에 없지만 필요한 파일"이 생겨 계획-구현 대응이 깨진다.

## [N]. 구현 슬라이스 계획   ← 항상 마지막 장. 제목 문자열을 고정으로 유지할 것

> 「프로젝트 구조」 장의 모든 파일이 아래 표에 **정확히 한 번씩** 등장해야 한다.

## 슬라이스 분해 규칙

### 소유권 — 파일 하나는 슬라이스 하나
- 각 파일은 **정확히 한 슬라이스**의 표에만 체크 항목으로 등장한다
- 다른 슬라이스에서 그 파일을 쓰면 표의 `의존` 열에 `(F0)`처럼 소유 슬라이스를 병기만 한다
- 여러 기능이 나눠 확장해야 하는 단일 파일(스키마, 라우팅 설정, 메시지 카탈로그 등)은 **F0가 소유하고 한 번에 전부 정의**한다 — 슬라이스마다 같은 파일을 다시 여는 것을 금지

### 배치 기준
- 2개 이상 기능이 공유 → **F0**
- 한 기능만 사용 → 해당 기능 슬라이스 (해당 기능의 테스트도 같은 슬라이스)

### 크기 상한
- 한 슬라이스가 **25항목을 초과**하면 `F2a` / `F2b`로 분할하고 「슬라이스 목록」 표에 둘 다 기재
- 분할 기준은 계층이 아니라 **독립 검증 가능 단위** (예: F2a 주문 생성 / F2b 결제 확정·웹훅)

### 실행 작업 항목 (⚙️)
파일 생성이 아니지만 **반드시 수행돼야 하는 명령**은 `⚙️` 접두어를 붙여 체크 항목으로 넣는다.
- `⚙️ npm install` — 의존성 설치. **F0에 반드시 포함** (없으면 이후 모든 게이트가 실패한다)
- `⚙️ npx prisma migrate dev` — 마이그레이션 적용 등 스키마 반영 명령
- 「프로젝트 구조」 파일 수 대조 시 `⚙️` 항목은 **세지 않는다** (파일이 아니므로)

### 완료 게이트
- 슬라이스마다 그 시점에 **실제로 통과 가능한** 검증 명령을 적는다
- 아직 존재하지 않는 페이지를 요구하는 E2E 명령을 F0 게이트로 두지 않는다

## 주의사항
- PRD 없이 작성 시도 시 중단하고 안내
- PRD의 모든 기능을 빠짐없이 매핑
- 파일 경로는 실제 생성될 경로로 명시
- 함수명은 구현 시 그대로 사용할 수 있도록 구체적으로
- 기술 스택 선정에 근거 포함
- ❌ 「구현 슬라이스 계획」 장 없이 TECH_SPEC을 완료 처리 금지 (`/sdd-build`가 동작 불가)
- ❌ 「구현 슬라이스 계획」 장 제목을 변형하지 말 것 (하위 스킬이 제목으로 찾음)
- ❌ 같은 파일을 두 슬라이스에 중복 기재 금지
- ✅ 「프로젝트 구조」 파일 수 == 슬라이스 계획 항목 수(⚙️ 제외) 자체 확인 후 종료
