# /sdd-build - 코드 구현

## 동작
`docs/TECH_SPEC.md`의 **「구현 슬라이스 계획」 장**을 추출해 `docs/tasks/` 아래 슬라이스별 작업 문서를 만들고,
슬라이스마다 @developer 에이전트를 호출하여 구현·검증합니다.

> **계획을 다시 세우지 않습니다.** 계획은 `/sdd-design`에서 이미 확정됐습니다.
> 이 스킬이 하는 일은 추출(기계적) → 슬라이스별 구현 → 게이트 검증뿐입니다.
> 오케스트레이션(에이전트 호출)은 이 스킬에서만 수행합니다. @developer는 서브 에이전트를 호출하지 않습니다.

## 사용법
```
/sdd-build              # 전체 슬라이스 순차 실행
/sdd-build F2           # 특정 슬라이스만 실행 (재시도/이어서 작업)
```

## 전제조건
- **docs/PRD.md 필수**: 기능 요구사항 참조
- **docs/TECH_SPEC.md 필수**: 구현 명세 + 마지막 장 「구현 슬라이스 계획」
- 둘 중 하나라도 없으면 → 해당 단계 안내 후 중단

## 실행 순서

### Step 1: 전제조건 체크
```
docs/PRD.md 존재 확인
├── 미존재 → "/sdd-plan을 먼저 실행해주세요." 중단
└── 존재 → docs/TECH_SPEC.md 확인
    ├── 미존재 → "/sdd-design을 먼저 실행해주세요." 중단
    └── 존재 → "구현 슬라이스 계획" 제목의 장 검색 (장 번호가 아니라 제목으로 찾을 것)
        ├── 미존재 → "TECH_SPEC에 「구현 슬라이스 계획」 장이 없습니다. /sdd-design을 다시 실행해주세요." 중단
        └── 존재 → Step 2로 진행
```

### Step 2: 슬라이스 계획 추출

**「구현 슬라이스 계획」 장만 읽습니다. PRD와 TECH_SPEC 전문을 이 시점에 읽지 않습니다** — 스펙 상세는 각 슬라이스 구현 시 @developer가 필요한 부분만 읽습니다.

1. 「슬라이스 목록」 표 → 슬라이스 ID·이름·선행 관계 파악
2. 슬라이스별 표 → 그대로 체크리스트로 전사 (판단·재배치·추가 금지)
   - `⚙️` 접두 항목은 파일이 아니라 **실행 명령**이므로 그대로 옮기고 체크 대상에 포함
3. 추출 검증: 「슬라이스 목록」의 `항목 수` 합계 == 전사한 체크박스 총 개수
   - 불일치 → 사용자에게 보고하고 `/sdd-design` 재실행 권고, 중단

### Step 3: 작업 문서 작성

파일명 규칙: `docs/tasks/{슬라이스ID}-{영문 슬러그}.md`

```
docs/
├── TASK.md              # 슬라이스 인덱스 (전체 진행률)
└── tasks/
    ├── F0-foundation.md
    ├── F1-[슬러그].md
    └── F2-[슬러그].md
```

기존 `docs/tasks/` 문서가 있을 때:
- 덮어쓰지 말고 사용자에게 이어서 진행할지 확인
- 이어서 진행 시 → 계획과 기존 문서를 대조
  - 계획에만 있는 항목 → 해당 슬라이스 문서 끝에 `- [ ]`로 **추가**
  - 기존 문서의 `- [x]` → 그대로 보존
  - 계획에서 사라진 항목 → 삭제하지 말고 `(계획에서 제거됨)` 표기 후 사용자에게 보고

### Step 4: 실행 대상 결정

| 호출 | 대상 |
|---|---|
| `/sdd-build` | 미완료 슬라이스 전부 (선행 관계 순서) |
| `/sdd-build F2` | F2만. 단 **선행 슬라이스가 전부 완료됐는지 먼저 확인** |

선행 슬라이스에 미완료 항목이 있으면 → "F2의 선행 F0이 미완료입니다(3/13). 선행부터 진행할까요?" 확인 후 결정.

### Step 5: 슬라이스 실행 루프

「슬라이스 목록」의 선행 관계 순서대로 **슬라이스마다 아래를 반복**합니다.

```
for 슬라이스 in 실행 대상:
    5-1. @developer 호출 — 전달 항목:
         - 담당 슬라이스 ID와 해당 task 문서 경로 1개
         - TECH_SPEC에서 참조할 절 제목 (해당 슬라이스 파일들의 구현 명세)
         - "이 슬라이스 밖의 파일은 생성/수정하지 말 것"
         → @developer가 구현 + 게이트 자체 실행까지 수행하고 결과를 보고
    5-2. task 문서 전 항목 [x] 확인
         └── 미완료 남으면 → 남은 항목만 명시하여 같은 슬라이스 재호출
    5-3. 게이트 독립 재실행 (호출자가 직접 실행하여 @developer 보고를 검증)
         ├── 실패 → 실패 로그를 붙여 @developer에 수정 요청 (최대 2회)
         │           2회 후에도 실패 → 사용자에게 보고하고 진행 여부 확인
         └── 성공 → 5-4
    5-4. docs/TASK.md 인덱스 진행률 갱신 → 다음 슬라이스
```

> **게이트는 두 번 돕니다.** @developer가 자기 작업을 닫기 위해 한 번(5-1), 호출자가 보고를 믿지 않고 한 번(5-3).
> 순서가 `항목 완료 확인(5-2) → 게이트(5-3)`인 이유: 미완료 항목이 남은 상태의 게이트 실패는 진단 가치가 없기 때문입니다.

**슬라이스 경계가 컨텍스트 리셋 지점입니다.** 슬라이스 하나가 끝나면 다음 @developer는 이전 슬라이스의 구현 과정을 물려받지 않고, 완성된 코드와 자기 task 문서만 봅니다.

### Step 6: 진행 상황 보고

슬라이스 단위로 보고합니다.

```
▶ F0 공통 기반 (14항목)
  [1/14] package.json ✅
  [2/14] ⚙️ npm install ✅
  ...
  [14/14] vitest.config.ts ✅
  게이트: npx tsc --noEmit ✅

▶ F1 템플릿 탐색·미리보기 (9항목)
  ...
```

### Step 7: 완료 확인
- 모든 슬라이스의 task 문서에 미완료(`- [ ]`) 항목이 없는지 확인
- 남아 있으면 → 중단하지 말고 해당 슬라이스를 재실행
- 전부 완료된 경우에만 완료 메시지 출력

## 문서 템플릿

```markdown

> 출처: docs/TECH_SPEC.md 「구현 슬라이스 계획」
> 슬라이스별 체크리스트는 docs/tasks/ 참조

| 슬라이스 | 이름 | 진행 | 게이트 | 문서 |
|---|---|---|---|---|
| F0 | 공통 기반 | 14/14 | ✅ | [F0-foundation.md](tasks/F0-foundation.md) |
| F1 | 템플릿 탐색·미리보기 | 0/9 | - | [F1-templates.md](tasks/F1-templates.md) |

**전체: 14/63**
```

### docs/tasks/F1-[슬러그].md (슬라이스 체크리스트)

```markdown
# F1 — [슬라이스 이름]

> 출처: docs/TECH_SPEC.md 「구현 슬라이스 계획」 / 대응 PRD 기능: 기능 1
> 선행 슬라이스: F0 (완료 필요)
> 완료 게이트: `npx tsc --noEmit && npm run test:unit`
> 파일 완성 시 즉시 체크. 일괄 체크 금지. 이 문서에 없는 파일 생성 금지.

## 체크리스트

- [ ] `src/server/templates/preview.ts` — 미리보기 마스킹 (의존: types/domain.ts@F0) (F1-AC5, F1-AC6)
- [ ] `src/components/TemplateCard.tsx` — 목록 카드 (의존: preview.ts) (F1-AC1)

## 수용 기준 매핑
| PRD 수용 기준 | 담당 파일 |
|---|---|
| F1-AC1 템플릿 목록을 볼 수 있다 | TemplateCard.tsx, template.service.ts |
```

## 출력물
- `docs/TASK.md` (슬라이스 인덱스)
- `docs/tasks/*.md` (슬라이스별 체크리스트)
- `src/` 폴더 내 코드 파일들
- 프로젝트 설정 파일들

## 주의사항
- ❌ Plan 에이전트로 구현 계획을 다시 수립 금지 (계획은 TECH_SPEC 「구현 슬라이스 계획」이 유일 출처)
- ❌ 계획에 없는 파일을 임의로 추가 금지 — 필요 시 사용자에게 보고 후 TECH_SPEC 갱신
- ❌ 장을 번호로 찾기 금지 (프로젝트마다 장 번호가 다름 — **제목으로 검색**)
- ❌ 한 번의 @developer 호출에 여러 슬라이스를 몰아서 맡기기 금지
- ❌ 게이트 실패를 다음 슬라이스로 넘기기 금지
- ✅ 슬라이스 완료 시마다 인덱스 갱신

```
🚀 실행 방법: npm run dev

다음 단계: /sdd-review 로 스펙 검증을 수행하세요.
```
