# 주식 시장 분석 스킬

## 역할

공개 데이터를 수집해 종목을 **정량 분석 + 정성 분석 + 시장 심리**의 세 축으로 검토하고,
표준 양식의 분석 보고서를 작성합니다.

이 스킬의 핵심 원칙은 **모든 수치에 출처가 있어야 한다**는 것입니다. 기억에 의존해 PER을
쓰거나 실적을 추정하지 마세요. 주가와 재무 수치는 매일 바뀌고, 틀린 숫자 위에 세운 분석은
그럴듯할수록 더 위험합니다. 번들 스크립트로 실제 데이터를 먼저 가져온 뒤 해석하세요.

---

## 구성 파일

| 경로 | 언제 읽나 |
|---|---|
| `scripts/market_data.py` | 데이터 수집 시 실행 (읽지 말고 실행) |
| `scripts/export_report.py` | 완성한 보고서를 PDF로 변환할 때 실행 |
| `scripts/position_calc.py` | 포지션 크기·손익비를 계산할 때 실행 (@trade-planner 전용) |
| `references/quantitative.md` | PER/PBR/ROE 등 지표를 해석할 때 |
| `references/qualitative.md` | 해자·산업구조·리스크를 분석하고 웹 검색으로 정성 정보를 모을 때 |
| `references/market-sentiment.md` | 공포탐욕지수·VIX·금리·수급을 해석할 때 |
| `references/data-sources.md` | 스크립트가 실패했거나 소스를 확장할 때 |
| `assets/report-template.md` | 보고서를 작성할 때 (그대로 복사해 채움) |

레퍼런스는 필요한 것만 읽으세요. 단순 시세 조회에 4개를 모두 읽을 필요는 없습니다.

## 데이터 수집: `scripts/market_data.py`

표준 라이브러리만 쓰므로 설치가 필요 없습니다. 스킬 디렉터리 기준 경로로 실행하세요.

```bash
python scripts/market_data.py <명령> <종목...> [--range 1y] [--format json|text]
```

| 명령 | 용도 |
|---|---|
| `search <검색어>` | 종목명으로 티커/코드 찾기 (한글·영문, 한국·미국 모두) |
| `quote <종목...>` | 현재가, 전일대비, 52주 고저 및 밴드 내 위치 |
| `technicals <종목...>` | RSI(14), SMA 20/60/120 및 이격도, 변동성, MDD, 기간 수익률 |
| `fundamentals <종목...>` | 밸류에이션·수익성·재무건전성·애널리스트 컨센서스 (+국내는 수급) |
| `peers <종목>` | 동종업계 비교 종목 (국내는 목록, 미국은 sector/industry) |
| `sentiment` | 공포탐욕지수, VIX, 주요 지수·금리·환율·원자재 |
| `report <종목>` | 위 전부를 한 번에 수집 (**종목 분석의 기본 진입점**) |

### 종목 지정 방법

세 가지를 모두 받아들이며, KOSPI/KOSDAQ 접미사는 자동으로 판별합니다.

```bash
python scripts/market_data.py report 005930      # 6자리 코드 → 005930.KS
python scripts/market_data.py report 247540      # → 247540.KQ (코스닥 자동 인식)
python scripts/market_data.py report AAPL        # 미국 티커
python scripts/market_data.py report "삼성전자"   # 한글 종목명 → 검색 후 자동 해석
```

한글 종목명으로 넘기면 결과의 `resolved_from` 에 어떤 후보 중에서 골랐는지가 담깁니다.
동명의 ETF나 유사 종목이 있을 수 있으니 **이 필드를 확인해 의도한 종목이 맞는지 검증**하세요.
애매하면 `search` 로 후보를 먼저 보여주고 사용자에게 확인받는 편이 낫습니다.

### 사용 예

```bash
# 종목 하나를 제대로 분석할 때 — 이것 하나로 시작
python scripts/market_data.py report "에코프로비엠" --format text

# 여러 종목 동시 비교
python scripts/market_data.py fundamentals 005930 000660 AAPL

# 시장 분위기만 확인
python scripts/market_data.py sentiment --format text

# 장기 추세를 볼 때
python scripts/market_data.py technicals NVDA --range 5y
```

`--format text` 는 사람이 읽기 좋은 요약이고, 기본값 `json` 은 전체 필드를 담습니다.
직접 해석해서 보고서를 쓸 때는 정보량이 많은 `json` 이 유리합니다.

### 부분 실패 처리

`report` 와 `sentiment` 는 일부 소스가 실패해도 나머지를 반환하고 `errors` 키에 실패 내역을
기록합니다. **수집되지 않은 값을 추정으로 메우지 마세요.** 보고서에 "데이터 미수집"으로
표기하고, 그 항목에 의존하는 결론은 유보하는 것이 정직한 처리입니다.
실패가 반복되면 `references/data-sources.md` 의 트러블슈팅 표를 확인하세요.

## 분석 워크플로우

### 1단계 — 요청 범위 파악

사용자가 무엇을 원하는지에 따라 깊이를 조절하세요. 단순 시세 질문에 전체 보고서를
내미는 것은 과잉이고, "분석해줘"에 숫자만 던지는 것은 부족합니다.

| 요청 유형 | 대응 | 문서화 |
|---|---|---|
| "지금 얼마야?" | `quote` 만 실행하고 간단히 답변 | 불필요 |
| "시장 분위기 어때?" | `sentiment` + `references/market-sentiment.md` | 불필요 |
| "재무 상태만 봐줘" | `fundamentals` + `references/quantitative.md` | 선택 |
| "이 종목 어때?" / "분석해줘" | 전체 워크플로우 (2~5단계) | **필수** |
| "A랑 B 중 뭐가 나아?" | 두 종목 `report` 후 비교 분석 | **필수** |
| "보고서 만들어줘" / "PDF로 저장해줘" | 전체 워크플로우 후 6단계 | **필수** |
| "매매 계획 세워줘" / "얼마에 사고 팔까?" | 분석 후 `@trade-planner` 로 인계 (7단계) | **필수** |

단순 조회에 파일을 만드는 것은 과잉입니다. 반대로 전체 분석을 해놓고 대화창에만
남기면 사용자가 나중에 참조할 방법이 없으니, 분석을 수행했다면 6단계까지 진행하세요.

**"그래서 사야 돼?" 류의 질문을 받으면** 분석 결과를 제시하되 매수·매도 지시는 하지
마세요. 이 스킬은 판단 재료를 만드는 도구이고, 실행 조건 설계가 필요하면 `@trade-planner`
가 담당합니다. 그 에이전트 역시 권유가 아니라 조건부 규칙을 설계합니다.

### 2단계 — 정량 데이터 수집

```bash
python scripts/market_data.py report <종목> --format json
```

수치를 해석하기 전에 `references/quantitative.md` 를 읽으세요. **지표 하나만으로 판단하지
않는 것**이 핵심입니다. PER은 동종업계·자사 과거·이익성장률 세 가지와 비교해야 의미가
생기고, 반도체 같은 사이클 산업에서는 저PER이 오히려 업황 정점 신호일 수 있습니다.

### 3단계 — 정성 정보 수집

스크립트가 주는 것은 숫자입니다. **왜 그런 숫자가 나왔고 앞으로도 유지될지**는 웹 검색으로
보강해야 합니다. WebSearch/WebFetch로 다음을 확인하세요.

- 최근 실적 발표와 그 배경 (국내: DART 사업보고서 / 미국: SEC 10-K, 10-Q)
- 경영진 가이던스와 컨센서스 변화
- 산업 동향, 경쟁 구도 변화, 규제 이슈

`references/qualitative.md` 에 소스별 접근 경로와 검색 질의 예시, 정보 신뢰도 등급표가
있습니다. **공시(A등급)가 언론 보도(C등급)보다 우선**하며, 검색 결과의 날짜를 반드시
확인하세요 — 몇 년 지난 전망 기사가 상위에 노출되는 일이 흔합니다.

### 4단계 — 시장 심리 확인

`report` 에 이미 포함되어 있습니다. `references/market-sentiment.md` 를 참고해 해석하되,
심리 지표는 **배경 조건**일 뿐 개별 종목 판단을 대체하지 않습니다. 공포탐욕지수의 절대
수준보다 1주/1개월 전 대비 변화 방향이 더 유의미한 정보인 경우가 많습니다.

### 5단계 — 보고서 작성

`assets/report-template.md` 를 그대로 가져와 채우세요. 섹션 순서는 유지합니다 — 결론을
먼저 제시하고(1. 요약) 근거를 전개하는 구조라, 사용자가 어디까지 읽든 핵심을 얻습니다.

해당 데이터가 없는 섹션은 삭제하지 말고 **"데이터 미수집" 또는 "해당 없음"으로 남기세요.**
빈칸이 있다는 사실 자체가 분석의 한계를 보여주는 정보입니다.

### 6단계 — `output/` 폴더에 문서화

전체 분석을 수행했다면 **결과를 대화창에만 남기지 말고 파일로 저장하세요.** 보고서는
나중에 다시 열어보고 판단을 검증하는 데 쓰이는 기록물입니다.

작업 디렉터리 기준 `output/` 폴더에 마크다운으로 먼저 쓰고, 같은 파일을 PDF로 변환합니다.

```bash
# 1) output/ 에 마크다운 보고서 작성 (Write 도구 사용)
#    파일명 규칙: output/<종목명>_<YYYYMMDD>_분석보고서.md
#    예: output/삼성전자_20260805_분석보고서.md

# 2) 같은 이름의 PDF 생성
python scripts/export_report.py output/삼성전자_20260805_분석보고서.md
```

결과물 두 개가 나란히 남습니다.

```
output/
├── 삼성전자_20260805_분석보고서.md
└── 삼성전자_20260805_분석보고서.pdf
```

**날짜를 파일명에 반드시 넣으세요.** 같은 종목을 다른 시점에 분석하면 별도 파일로 쌓여
판단의 변화를 추적할 수 있습니다. 날짜가 없으면 덮어쓰기가 되어 이력이 사라집니다.

`export_report.py` 는 시스템에 설치된 Chrome 또는 Edge를 헤드리스로 사용해 PDF를 만듭니다.
A4 인쇄 레이아웃, 한글 폰트, 표 페이지 분할 방지가 적용되어 있습니다.

| 옵션 | 용도 |
|---|---|
| `-o <경로>` | PDF 출력 위치를 따로 지정 |
| `--keep-html` | 중간 HTML을 남김 (스타일 확인용) |
| `--html-only` | 브라우저 없이 HTML만 생성 |

브라우저를 찾지 못하면 `CHROME_PATH` 환경변수로 경로를 지정하거나, `--html-only` 로
HTML까지만 만들고 사용자에게 상황을 알리세요. **PDF 변환에 실패했다고 해서 마크다운
보고서까지 버리지 마세요** — 마크다운이 본체이고 PDF는 배포용 사본입니다.

작업을 마치면 생성된 파일의 실제 경로를 사용자에게 알려주세요.

### 7단계 (선택) — 매매 계획으로 연결

사용자가 보고서를 넘어 **실행 계획**(진입·손절·목표 가격대, 매수 수량, 청산 조건)을
원하면 `@trade-planner` 에이전트로 넘기세요. 이 스킬은 "이 종목이 어떤 상태인가"까지
답하고, 그 다음 "그래서 어떻게 실행할 것인가"는 별도 역할입니다.

@trade-planner는 보고서의 **반증 조건을 청산 트리거로 번역**하고, 사용자가 제시한
리스크 한도로 `scripts/position_calc.py` 를 돌려 포지션 크기와 손익비를 산출합니다.
결과는 `output/<종목명>_<YYYYMMDD>_매매계획.md` 로 저장됩니다.

넘기기 전에 확인할 것: **보고서의 7장(종합 결론)에 반증 조건이 실제로 적혀 있어야
합니다.** 이것이 매매 계획의 재료이므로, 비어 있으면 계획도 근거를 잃습니다.

## 보고서 품질 기준

좋은 분석과 나열의 차이는 아래에서 갈립니다.

**1. 표만 두지 말고 해석을 붙입니다.**
`PER 19.88배`는 데이터고, "동종업계 평균 12배 대비 65% 할증인데, 선행 PER이 5.13배로
급락하는 것은 시장이 내년 이익 급증을 반영하고 있기 때문"은 분석입니다.

**2. Bull과 Bear를 모두 씁니다.**
한쪽만 쓴 보고서는 분석이 아니라 주장입니다. 반대 논거를 진지하게 검토했다는 것을
보여야 결론에 신뢰가 생깁니다.

**3. 반증 조건을 명시합니다.**
"무엇이 관찰되면 이 판단을 바꿔야 하는가"를 적으세요. 이것이 보고서에서 가장 실용적인
부분입니다. 사용자는 이 조건을 기준으로 이후를 추적할 수 있습니다.

**4. 추정치와 확정치를 구분합니다.**
`forward_per`, `cnsPer`, `consensus_periods` 에 해당하는 값은 애널리스트 **예상**입니다.
확정 실적과 나란히 두되 예상임을 반드시 표기하세요.

**5. 관측 시점을 기재합니다.**
주가와 심리 지표는 하루 만에도 바뀝니다. 분석 기준일이 없는 보고서는 며칠 뒤면
쓸모를 잃습니다.
